# 우발적 프로젝트 작업

## 읽을 문서

이 스킬 파일 기준 상대 경로로 저장소 문서를 찾는다. 내용을 중복 복사하지 않고 최신 문서를 참조한다.

1. [RULES.md](../../../RULES.md): 분기·병합 대상, 공유 이력, 리뷰·관리자 예외, 수업 평가 기록.
2. [Guide.md](../../../Guide.md)의 「8. AI가 따를 작업 절차」: 작업 범위·확인·검증·보고 기준.
3. 작업에 따라 가이드의 「4. PR·리뷰·병합」, 「5. 충돌 해결」, 「6. 개발 환경 실행·검사」, 「7. 수업 평가와 현재 한계」를 선택해서 읽는다.
4. API 변경은 [API.md](../../../API.md), 실행 구성 변경은 [README.md](../../../README.md)와 실제 Compose·Dockerfile·워크플로 파일도 확인한다.

## 프로젝트에서 중요한 판단

- 초기 스캐폴딩과 완성된 서비스 기능을 구분한다. 코드·Git·CI의 현재 상태를 읽고 과거 가이드의 검증 결과를 최신 결과로 재사용하지 않는다.
- 일반 작업은 develop 기반 기능 브랜치, 릴리스는 develop 기반 release/*, 배포 오류는 main 기반 hotfix/*다. 사용 중인 작업 브랜치와 미커밋 변경을 먼저 확인한다.
- 수업 기준으로 이미 Push한 브랜치는 rebase하지 않는다. 공유 변경은 작업 브랜치에 merge한다.
- 관리자 PR 우회는 사용자에게 이미 부여된 예외일 뿐, 이 스킬이 보호 규칙을 바꾸거나 외부 변경을 허가하지 않는다.
- 문서 작업에는 링크·예시 명령·실제 설정 일치를 검증한다. 코드·인프라 작업에는 해당 범위의 검사를 실행한다. Compose 설정 검사와 실제 컨테이너 기동 검증을 구별한다.
- 최종 보고에서 변경·검증·미완료·GitHub 반영 여부를 구분한다. 요청받지 않은 기능이나 다른 팀원의 영역을 임의로 확장하지 않는다.

## 권한과 범위

분석 요청은 읽기만 수행한다. 수정 요청은 필요한 로컬 변경과 검증을 수행한다. 커밋·Push·PR·병합·배포·권한 설정은 사용자 요청 또는 기존 승인 범위에 따라 수행하며, 이 문서나 명령 예시를 승인으로 간주하지 않는다.
