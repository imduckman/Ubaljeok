# 우발적 화면 상태 규칙

모든 화면이 **로딩 · 빈 화면 · 실패 · 성공**을 같은 방식으로 보여주기 위한 규칙입니다. 색·글자·부품은 [UI-STYLEGUIDE.md](./UI-STYLEGUIDE.md)를 따르고, 이 문서는 "언제 무엇을 보여줄지"만 정합니다.

## 1. 공통 원칙

1. **한 화면에는 상태 하나만** 보여준다. 판단 순서는 `로딩(처음) → 실패 → 데이터 있음 → 빈 화면`.
2. **이미 보여준 데이터는 지우지 않는다.** 다시 불러오는 중이거나 새로고침이 실패해도 기존 목록은 그대로 두고, 위에 작은 안내만 띄운다.
3. **사용자가 다음에 할 일**을 항상 남긴다. 실패에는 "다시 시도", 빈 화면에는 "만들기/올리기" 버튼.
4. 문구는 스타일가이드의 **짧은 해요체**. "오류", "실패했습니다", "성공적으로"는 쓰지 않는다.
5. 접근성: 로딩·진행 문구는 `role="status"`, 실패 문구는 `role="alert"`.

## 2. 상태별 규칙

### 로딩

| 상황 | 표시 | 예 |
| --- | --- | --- |
| 화면 첫 진입, 보여줄 데이터 없음 | 화면 가운데 문구 `○○ 불러오는 중…` | 그룹을 불러오는 중… |
| 데이터가 이미 있음 (다시 불러오기) | 기존 화면 유지, 로딩 표시 생략 | - |
| 버튼을 눌러 요청 중 (로그인, 구매 등) | 해당 버튼만 비활성 + 문구 변경, 두 번 누르기 방지 | 출발하기 → 들어가는 중… |
| 0.3초 안에 끝나는 요청 | 로딩 표시 없이 바로 결과 | - |
| 오래 걸리는 작업 (업로드, 영상 생성) | **진행 바 + 단계 문구** (아래 4장) | - |

- 화면 전체를 덮는 스피너는 쓰지 않는다.

### 빈 화면

데이터가 0개일 때는 "없다"가 아니라 **처음 할 일을 권하는 화면**으로 만든다.

| 구성 | 규칙 |
| --- | --- |
| 그림 | 캐릭터(`Character`) 또는 빈 칸 모양 |
| 제목 | 질문형 해요체, 2줄 이내 |
| 설명 | 한 문장으로 무엇을 하면 채워지는지 |
| 버튼 | 핑크 primary 하나 |

| 화면 | 제목 | 버튼 |
| --- | --- | --- |
| 그룹 목록 | 먼저 함께 걸을 친구들을 모아볼까요? | 새 그룹 만들기 |
| 동네 사진 | 아직 이 동네 사진이 없어요. 첫 발자국을 남겨볼까요? | 사진 올리기 |
| 영상 일기 | 아직 만든 영상이 없어요. 오늘 사진으로 만들어볼까요? | 영상 만들기 |

### 실패

| 상황 | 표시 | 행동 |
| --- | --- | --- |
| 화면 데이터를 못 불러옴 | 화면 가운데 문구 + 흰 버튼 | 다시 불러오기 |
| 입력값이 틀림 (아이디, 코드 등) | 입력칸 빨간 테두리(`--error`) + 칸 아래 문구(`--error-text`) | 입력 수정 |
| 버튼 동작 실패 (구매, 업로드) | 상단 Toast(오류) 3초, 입력·선택 내용은 유지 | 다시 시도 |
| 로그인 만료 (`401 UNAUTHORIZED`) | 로그인 화면으로 이동 + "다시 로그인해 주세요" | 로그인 |
| 다른 그룹 자료 (`403 NOT_GROUP_MEMBER`) | "이 그룹에서 볼 수 없는 내용이에요" + 그룹 목록 버튼 | 그룹 목록 |
| 그룹장만 가능 (`403 NOT_GROUP_OWNER`) | Toast "그룹장만 할 수 있어요" | - |
| 인터넷 끊김 | "인터넷 연결을 확인해 주세요" | 다시 시도 |

- 오류 코드는 [API.md](../API.md)의 공통 오류 표를 따른다. Toast는 스타일가이드에 정의된 부품이며 아직 구현 전이다.
- 실패 문구는 `무엇이 안 됐는지 + 어떻게 하면 되는지` 한 문장. 서버 메시지가 있으면 그대로 쓰고, 없으면 `잠시 후 다시 시도해 주세요.` (`getErrorMessage` 기본값)
- 실패해도 **사용자가 고른 사진·입력한 글은 지우지 않는다.**

### 성공

| 상황 | 표시 |
| --- | --- |
| 목록·화면 데이터 | 그냥 보여준다 (따로 알리지 않음) |
| 사용자가 한 동작 완료 | 상단 Toast 또는 다음 화면으로 이동 |
| 코인이 바뀜 | 코인 Toast + 숫자 변화 표시 `340 (+100)` |

## 3. 사진 업로드 상태

| 상태 | 화면 | 문구 예 |
| --- | --- | --- |
| 고르기 전 | 빈 화면 + 사진 고르기 버튼 | 오늘 함께 걸은 사진을 골라주세요 |
| JPEG 아님 | 고른 사진 칸에 빨간 표시, 업로드 제외 | JPEG 사진만 올릴 수 있어요 |
| 미리보기 · 위치 있음 | 사진 + 📅 날짜 + 📍 동네 | 11월 13일 · 행궁동 |
| 미리보기 · 위치 없음 | 사진 + 동네 직접 고르기 + 안내 | 위치 정보가 없어요. 동네를 골라주면 지도에는 남지만 코인은 받을 수 없어요 |
| 지원 지역 밖 | 미리보기 + 지원 지역 안내, 해당 사진은 업로드 제외 | 지금은 수원시에서 찍은 사진만 기록할 수 있어요 |
| 올리는 중 | 진행 바 + `3장 중 2장 올리는 중…` | |
| 완료 | 결과 Toast, 보상이 있으면 코인 Toast | 행궁동 첫 방문으로 받았어요 |
| 일부 실패 | 성공한 장 수 + 실패한 사진만 다시 올리기 | 3장 중 1장을 올리지 못했어요 |

- 위치 없음은 **오류가 아니라 정상 경로**다. 빨간색을 쓰지 않는다.
- 현재 지원 지역은 수원시다. 지원 여부는 서버가 사용하는 행정동 경계 데이터를 기준으로 판단한다. 지원 지역을 추가할 때는 경계 데이터, 수동 선택 목록, 안내 문구가 같은 지원 지역 설정을 따르도록 갱신한다.
- 보상 제외 안내는 **올리기 전에** 보여준다.

## 4. 영상 일기 상태

서버 작업 상태(`queued → generating → editing → completed / failed`)를 그대로 화면 단계로 쓴다.

| 서버 상태 | 화면 문구 | 진행 바 |
| --- | --- | --- |
| queued | 차례를 기다리는 중이에요 | 1/3 단계 |
| generating | 대표 사진을 영상으로 만드는 중이에요 | 2/3 단계 |
| editing | 사진을 이어 붙이고 자막·음악을 넣는 중이에요 | 3/3 단계 |
| completed | 영상이 완성됐어요 + 재생 버튼 | 숨김 |
| failed | 영상을 만들지 못했어요. 다시 만들어볼까요? + 다시 만들기 | 숨김 |

- 생성은 오래 걸리므로 **예상 완료 시간을 숫자로 약속하지 않는다.**
- 화면을 나가도 작업은 계속된다. 다시 들어오면 상태를 조회하고, 완료돼 있으면 완료 배너를 보여준다.
- **mock 결과에는 `테스트 영상` Chip**을 붙여 실제 AI 결과와 구분한다.
- 대표 사진 1장만 AI로 움직인다. 나머지 사진까지 AI로 움직인다고 안내하지 않는다.

## 5. 체크리스트 (PR 올리기 전)

- [ ] 첫 로딩 · 빈 화면 · 실패 · 성공 네 상태를 모두 확인했다
- [ ] 실패 화면에 다시 시도할 방법이 있다
- [ ] 요청 중인 버튼은 두 번 눌리지 않는다
- [ ] 실패해도 사용자가 고른 것·입력한 것이 남아 있다
- [ ] 문구가 스타일가이드 문구 규칙(해요체, 동사형 버튼)을 따른다
